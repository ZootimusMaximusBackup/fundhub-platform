# W1 — Staff telemetry: wire the writer to real work

Branch: `telemetry-writers-w1`
Status: **done**

---

## What changed, in plain language

We have a table that is supposed to answer "who on the team did what today."
Until now nothing ever wrote to it. It was empty.

Now, when someone on the Inquiry Remover desk logs a phone call or a mailed
letter on a client's file, we also save one small line that says: this person,
this shift, this client, this call. That line is what the team dashboard will
count later.

Nothing on any screen changed. Nobody has to do anything differently. The work
saves exactly the way it did before — we just also write down who did it.

**Two of the four things we were asked to count, we did not wire up, on
purpose.** They are:

- **Credit pulls.** Nobody on staff runs a credit pull in this system. The
  client pays, and the software runs the pull by itself. There is no employee to
  put on the line, so writing one would mean making a name up.
- **Text messages.** Same problem, bigger. Every text this system sends is sent
  by automation. There is no button anywhere that lets an employee send a text.
  So "texts sent by this person" is not a number this system can produce yet.

We could have picked a name and filled the blank. We did not. A made-up name in
a report is worse than a blank one, because a blank one is obviously missing.

---

## Decisions made, and why

**1. The line is written after the work is safely saved, never during.**
Saving the call and writing the telemetry line are two separate steps, in that
order. If they were one step, a problem writing the telemetry line could throw
away the call itself — the software would lose the real work in order to protect
the note about the work. Now the worst case is a missing note about a call that
still definitely happened.

**2. We wait for the line to finish writing.**
The telemetry writer is built so it can never crash anything — if it fails, it
quietly logs the failure and returns. So waiting for it costs a few milliseconds
and can never cost an outcome. Not waiting would cost the line: this runs on
Netlify, which stops the program the moment the web request is answered, so a
line we did not wait for is a line that sometimes silently never gets saved.

**3. The line says which shift the work fell on.**
The `TELEMETRY-CALLSITES.md` analysis flagged this as an open question with
three answers and no basis for choosing. It turned out there was a basis: the
web endpoint has to look up the person's open shift anyway, to decide whether
they are allowed to save at all. So we hand that answer down instead of looking
it up a second time. Correct answer, no extra database work.

**4. Notes and portal filings are not counted.**
- A *note* is already explicitly not an attempt in this code ("a desk that
  inflates its attempt count is lying to a bureau, slowly"). Counting it here
  would inflate the same number the existing code refuses to inflate.
- A *portal filing* — filing a dispute through a bureau's website — is real,
  counted, staff-performed work, and **the list of allowed telemetry names has
  no word for it.** We did not file it under "letter" to make it fit. That is a
  reported gap. See findings.

**5. We did not change the telemetry writer itself.** Out of scope, and it was
already correct.

## Findings

1. **Credit pulls have no staff actor anywhere in this system.** The pull is
   requested by an automated workflow when the client pays, and stored by
   another automated handler when the result comes back. Re-verified against
   `main`: there is no endpoint under `api/` that runs one. Counting pulls per
   employee is a product gap, not a wiring gap.

2. **There is no way for a staff member to send a text.** Every one of the
   outbound-message calls in this repo is inside an automated workflow. There is
   no "send message" button and no endpoint behind one. Same conclusion.

3. **Worth knowing before anyone counts texts later:** the message sender writes
   a row marked `queued` and nothing actually transmits it — there is no
   outbound network call anywhere in the adapters. A "text sent" count would
   currently mean "text queued", not "text reached a phone".

4. **Portal filings have no name in the telemetry vocabulary.** Real work, done
   by real people, that this telemetry cannot express. Adding a name is a
   decision for whoever owns the telemetry spec, not for a call site that needed
   a word.

5. **Automated letters still produce nothing.** Two workflows generate letter
   packs with no employee involved. Not wired, same reason.

6. **The auto-close sweep is still only as good as the telemetry.** It decides a
   shift is idle by looking for these rows. Only the Inquiry Remover desk
   produces them now. Closers, funding advisors and sales managers still produce
   none, so for them the sweep would still read every shift as idle from the
   moment it opened. **The sweep still has no caller and no scheduler, so nothing
   is harmed today** — but it must not be scheduled until the other roles have
   telemetry.

7. **`npm run lint` does not exist** in this repository (no `lint` script in
   `package.json`), and there is no TypeScript config for `npx tsc --noEmit`.
   Two of the six "definition of done" checks have nothing to run. Reported, not
   invented.

8. **There is no `docs/journeys/` directory.** The journey diagrams the working
   agreement describes are not in the repo, so there was no `-actual.md` to
   update and no `CHANGELOG.md` to append to. Reported, not created — inventing
   a journey file from one workflow's narrow view of one endpoint would be worse
   than the honest absence.

## Mutation test — every new guard was broken on purpose to prove a test catches it

| # | Guard broken | Test that failed | Reverted |
|---|---|---|---|
| 1 | Let a portal filing count as a letter | `a portal filing emits nothing — there is no kind for it, and it is not a letter` | yes |
| 2 | Default a missing outcome to `"unknown"` instead of leaving it blank | `the event carries the row it describes, and an unknown outcome stays unknown` | yes |
| 3 | Swap the two names — calls recorded as letters and letters as calls | `a call emits call_made, after the commit and never inside it`, `a letter emits letter_issued, not call_made` | yes |
| 4 | Write the telemetry line inside the transaction instead of after it | `a call emits call_made, after the commit and never inside it`, `logAttempt runs in a transaction and locks the row first` | yes |
| 5 | Stop passing the shift down from the endpoint | `a logged call writes one call_made row, on the shift it was worked on`, `a mailed letter writes letter_issued` | yes |

Every guard is protected by at least one named test. All files restored, full
suite re-run clean afterwards.

## Compliance

`COMPLIANCE REVIEW REQUIRED` — this touches the dispute-attempt path (calls and
letters to bureaus and furnishers on a consumer's dispute record).

To be clear about what it does and does not do: **no dispute behaviour changed.**
The attempt counter, the outcome, the confirmation timestamp and the attempt
history are all byte-for-byte what they were. What is new is an internal record
of which employee did the work, on which shift. That record contains no consumer
personal information beyond the internal id of the inquiry and the client — the
same ids already stored on the attempt row itself. It is never shown to a
client and is never sent anywhere.
