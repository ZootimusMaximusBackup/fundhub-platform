# W9 — Finance OS screen

`status: done` · branch `finance-os-ui-w9`

## What changed, in plain language

A new screen, **Finance OS**. It shows seven numbers about one client's credit
cards, read from their most recent credit pull:

1. Total credit limit
2. Total balance
3. Available credit
4. Utilization
5. Open revolving lines
6. Average APR (weighted by limit)
7. Cheapest money available

**Tradelines only.** Every number comes from credit-report card data and nothing
else. No bank data, no bills, no subscriptions — those are other builds. The
screen prints the word `tradelines` at the top so nobody has to guess what they
are looking at.

**The important part is what happens when a number is missing.** Credit files
have holes: a card that reports no limit, a card with no interest rate. When
that happens the row says so — it shows a `+` and a line reading
*"counted 2 of 3 lines · 1 did not report — this is a floor"*. A number with a
hole in it is a floor, not a total, and the screen says which it is.

And a client nobody has pulled yet shows **em dashes, not $0.00**. "We have not
checked" and "they have nothing" are opposite facts, and showing zero for the
first one tells a closer something false on a call.

## Decisions made (no questions asked, per the autonomy rules)

1. **Who can use it: `ROLE_SETS.STAFF`** — the same gate as
   `/api/read/tradelines`, which serves the very rows this endpoint adds up.
   Gating the summary more tightly than the detail would buy nothing: anyone
   refused here can read the underlying lines next door and add them up.
2. **The seven numbers are computed server-side**, in `src/finance/os-grid.mjs`.
   `closer-dashboard.html` already reimplements a funding waterfall in inline
   browser JavaScript against sample rows; a second implementation in a
   `<script>` block is a second answer that goes stale.
3. **Installment loans and closed cards are excluded**, matching
   `toCalculatorCards()` in `src/tradelines/index.mjs` — you cannot draw against
   an auto loan, and counting one inflates Available Credit, which is the single
   number a closer says out loud.
4. **APR is weighted by credit limit, not averaged flat.** 29% on a $500 card and
   12% on a $50,000 card do not cost the same; a flat mean describes no borrower.
5. **An unpriced card is never named as the cheapest money.** That is the worst
   possible direction to be wrong in.
6. **Utilization above 100% is reported, not clamped.** Being over limit is the
   thing a closer most needs to see.
7. **`FHData.read()`, not a new reader in `data.js`.** A named reader would be
   house style, but `data.js` is a shared file other parallel workflows are also
   editing, and `read()` already does the job.

## Findings

1. **The smoke test caught a real bug on its first run.** The screen called
   `FHData.get()`, which does not exist — `get` is private to `data.js`'s IIFE.
   The page silently kept its sample markup and no unit test could have seen it.
   Fixed to `FHData.read()`.
2. **Every screen in this repo parse-blocks on Google Fonts.** The webfont
   `<link>` sits in `<head>` and is render-blocking. In an environment with no
   direct outbound network the request HANGS rather than failing, so the HTML
   parser stops partway through `<head>`, `document.body` is never created, and
   the page sits at `readyState: "loading"` forever — with **zero console errors
   and zero failed requests**. A real visitor on a blocked or very slow network
   gets a blank page. This is not specific to Finance OS; it affects all 21
   screens. The smoke test blocks the font CDN so the page renders with fallback
   fonts, which is what such a visitor sees anyway. **Worth a decision:**
   `font-display: swap` is already in the URL, but that does not help when the
   stylesheet itself never arrives.
3. **`npm run lint` and `npx tsc --noEmit` do not exist in this repo** — no lint
   script, no TypeScript, no linter dependency. CLAUDE.md §6 requires both.
4. **`docs/journeys/` does not exist**, so there was no intended journey to read
   before building and no `-actual.md` to update. A new screen is exactly the
   kind of change §4 exists for; whoever owns the intended journeys should
   decide whether Finance OS belongs on the client journey.
5. **`WORKFLOW-AUTONOMY.md` does not exist** — not on this branch, not on `main`.

## Left undone

  subscriptions belong to W5-W8 and are not on `main`.
* No sidebar link beyond the `ALL` registration; the screen is reachable by URL
  and by the shell's own nav, and no existing screen links to it yet.
* No write path. The screen is read-only by design.
