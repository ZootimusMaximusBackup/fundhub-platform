# W1 — Demo Mode screen, nav entry, route

Read-only map. Nothing deleted.

## The screen

`public/app/sample-data.html` — 
titled "FundHub — Demo Mode" (`sample-data.html:6`, `:319`).

It is a **static file**, not a server route. It is served straight out of
`public/`. So it has **no entry in the hardcoded ROUTES map** in
`netlify/functions/api.mjs`, and deleting the file needs no ROUTES edit.
(The API endpoint it calls does live in ROUTES — that is W2's slice.)

What the screen does:
- Reads `GET /api/demo/mode`, shows ON/OFF and an eight-row COUNTS panel
  (`sample-data.html:363-410`).
- Turn ON / Turn OFF buttons.
- A "Wipe demo data…" button that deletes demo rows (`:341-352`).
- Gated in the browser: non owner/admin sees "Demo Mode is limited to owner and
  admin." and no fetch is made (`sample-data.html:369-376`).

## The nav entry — it is in 36 places, not one

The row is:
`<a class="navitem" href="sample-data.html"><span class="ico">⌗</span><span class="lbl">Demo Mode</span></a>`

It appears in:

1. `public/app/sidebar.fragment.html` — **the source of truth**.
2. `public/app/shell.js:31` — inside the one-line `SIDEBAR_HTML` string
   constant, between `==SIDEBAR_HTML_START==` and `==SIDEBAR_HTML_END==`.
   This is the copy that actually renders; `mountSidebar()` swaps out the
   inline copy on every page load.
3. Inline in **34 screen files** under `public/app/`.

**Do not hand-edit those 34 files.** `scripts/sync-sidebar.mjs` regenerates
them all from the fragment plus rewrites the shell.js constant. The correct
edit is: change `sidebar.fragment.html`, then run the sync script.

Guard tests that fail if these drift:
- `src/http/app-nav-matches-shell.test.mjs` — every inline sidebar must equal
  `SIDEBAR_HTML`.
- `src/http/app-nav-reachability.test.mjs` — sidebars must match each other.

## Role gating on the nav row

`public/app/shell.js:141` lists `sample-data.html` in `OWNER_ADMIN_ONLY`, with
a comment saying the row was moved there because `api/demo/mode.mjs` gates on
`requireRole("owner","admin")`. So today only owner and admin see the row.

`public/app/shell.js:27` also lists `sample-data.html` in `BETA_PAGES`, which
gives the row a BETA badge and the screen a dismissible beta banner.

## Tests that open the screen

- `e2e/screens-smoke.spec.mjs:40` — "loads without a JavaScript error".
- `e2e/crm-flows.spec.mjs:183` — "is interactive without throwing".

These are Playwright specs under `e2e/`, run by `npm run test:e2e`. They are
**not** in `npm test` (which globs `src/**` and `scripts/**` only).

## Intended journeys

`grep -i demo docs/journeys/*-intended.md` returns **one** hit, and it is not
about this screen: `role-sales-manager-intended.md:19` refers to a "demo login"
row created by `db/migrations/112_sales_manager_role.sql`.

**No intended journey describes the Demo Mode screen.** Deleting it does not
require an intended-journey edit. The `-actual.md` files do list
`/api/demo/mode` and `/api/demo/simulate` in their route tables — those are
generated by `npm run journeys` and will regenerate.
