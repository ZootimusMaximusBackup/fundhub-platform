**Rulebook:** `docs/UI-STANDARDS.md` · `.cursor/skills/fundhub-ui-auditor/SKILL.md`

**How:** `docs/workflows/ui-audit-evidence/_tools/ui-audit.mjs` (harness) + `_tools/BRIEF.md` (agent brief). One login per role, cached, screens run one at a time. 5 auditor agents (one per group), then one adversarial verifier per group re-checked every CRITICAL/HIGH against the evidence files and the code (`✓verified` = confirmed · `↓verifier` = downgraded, reason quoted · `+verifier-added` = the auditor missed it, the verifier found it in the same evidence).

## FIX RUN — 2026-08-17 night (runs 1–3)

**What this is.** The audit above found the problems. This section records what was *fixed*, by whom, and what is still open. Written by the orchestrator, not by the fixing agents — they returned manifests, one file each, so nobody edited this board while thirty agents were editing code.

**Two things changed about how the runs were built, and you should know why:**

1. **Agents were split by FILE, not by finding.** Four of the five patterns land in the same 26 screen files, and four of the fourteen CRITICALs sit two-to-a-file (campaign-manager, brand-studio, affiliate, client-portal). Two agents editing one file at the same time lose each other's work. So shared files (`fundhub-brand.css`, `shell.js`, `data.js`) got their own agent first, then one agent per screen applied every pattern that touched it.
2. **Evidence is captured ONCE, after the deploy — not per run.** The harness only works against `https://fundhub.ai`; local `netlify dev` answers 503 under a screen's normal read burst (recorded in the method notes above). Nothing fixed here exists on live until it is pushed. A screenshot taken before the deploy would be a picture of the unfixed screen. So: fix → lint → suite → push → deploy → capture. Rows say `FIXED-PENDING-EVIDENCE` until that capture happens, then `FIXED-UNCLICKED`.

**Baseline, measured on a clean worktree at `HEAD` before any change** (CLAUDE.md §12 says measure it yourself, so this was measured): `npm run lint` clean. `npm test` → **5449 tests, 5444 pass, 2 fail**, `DATABASE_URL` unset. The two failures are `the journeys are not stale` and `an endpoint excused from the org filter still passes the session's org to its store`. **Both fail before this work starts.** `npx tsc --noEmit` is listed in CLAUDE.md §6 but **there is no `tsconfig.json` in this repo** — the command just prints the compiler's help and exits 1. ## Method notes and harness limits (read before quoting a row)

- **Nothing was written.** Every non-GET `/api/**` request from the audit browser was intercepted (599). Rows that say a control "POSTs …" describe what the control *tried* to send; whether the role may send it comes from reading the handler's gate in `api/**.mjs`, and each such row says which gate was read.
- **`GONE`** in a click table = the harness could not find the control again after an earlier click changed the page (tab switch, filter emptied a list, Dismiss reloaded). Those controls were NOT exercised — rows say UNVERIFIED, not PASS.
- **`NOOP` false negatives:** the harness diffs page text/markup, not input values, so checkbox/toggle/preset clicks that only change `checked`/`value` read as NOOP (agent-editor 17, brand-studio Presets). Auditors re-checked those by hand and did not count them.
