## What changed on this screen

**The bar.** `banner()` built a fixed, full-width strip across the bottom of the
page in butter (`#F5CE8F`), mint (`#A8D8B0`) or rose (`#F2A69B`). It is gone. The
sentence it carried — "no client open", "demo mode", "could not load this file
(reason)", "live file · N payments · N messages" — is now written into the dark
status strip that was already at the foot of the screen, and the same fact is said
in words where the client's name goes, which is where a reader is already looking.
Nothing that was being said was dropped. A failed read is the one case that still
gets colour, and it is text, not a bar.

**The type.** `fundhub-brand.css:164` sets `font-size:inherit !important` on every
element inside `.app`, then hands sizes back to a fixed list of class names. Every
label on this screen was off that list, so all of them painted at 16px body size —
the same size as the value underneath — no matter what this file asked for. That
is the root of "the fonts are off". Fixed by joining the brand's vocabulary rather
than fighting it: titles carry `.card-title`, the next-action label carries
`.eyebrow` (mono, spectrum tick, from the brand file), and this screen's own
caption classes are handed the caption size in one rule that says why.
Field labels are sentence case now; only card titles are uppercase. Mono is data —
ids, money, counts — and one eyebrow.

**The cards.** Panels get the brand's resting shadow (`--panel-shadow`) and a 10px
radius, so an edge reads as an edge. The right rail's two sections became cards
like everything else instead of bare titles with content floating beside bordered
cards. Page and gutter are no longer black.

**Said twice, now said once.** The next action and the blocker list were each
painted into two boxes on this one screen — the old Blockers panel and the newer
Control panel — so the reader met the same sentence and the same list twice, both
saying the same thing. They are one card now. Both sets of slots are still wired
and still painted, because `src/http/client-panel-screen.test.mjs` requires both to
run through the guarded rule; the second set is `display:none`. Nothing is read
from the hidden copy.

**Layout and order.** Header is two rows: who this file is and the client picker,
then the eight tiles on an even grid that does not orphan the last one onto a row
of its own. Actions moved up to sit directly under the next action instead of
below two lists. The three bureau pulls sit on one row — same three buttons, same
ids, same handlers — because they are one choice, not three jobs.

**Empty state.** With no file open the screen used to print a dash where the
client's name goes and eight more dashes under it, which reads as a screen that
failed. It now says "No client open / Pick a client to open their file." and the
tile row and the funding-round grid step back to 45% instead of shouting dashes.
No value is invented and no unknown is painted as a number.

**Alarm that is always on.** The next-action panel used to sit in a coral wash
with a coral border at all times, so a clean file and a blocked one looked
identical. It is neutral now, and takes a coral left edge only when a blocker is
actually on screen — the same 4px status edge `pipeline.html` already uses.

**Top bar.** The screen's own name wrapped onto three lines and the clock broke in
half at 1440px once shell.js added Search, the role chip and Sign out. One line
now; the clock is the first thing dropped when the bar runs out of room.
