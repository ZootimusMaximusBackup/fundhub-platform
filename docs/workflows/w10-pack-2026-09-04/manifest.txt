preset spending limit, and nothing else. The vendor engine sums
`effectiveLimit || 0` (derive-consumer-signals.js:186), so its total limit is 0

zero-limit/ — the one open card REPORTS a credit limit, and it is $0
---------------------------------------------------------------------
NEW IN THE ROUND-3 VERIFIER REPAIR, and the reason that round exists. This is NOT
the same case as no-limit/ above, and treating the two as one is the whole
defect. The limit cell holds one of THREE things:

    a positive number   the file states a ceiling. 10% of it is a target.
    the number $0       the file states a ceiling of nothing. KNOWN, not missing.
    nothing at all      the file does not say.

The code asked only "is it null?", so the middle case computed round(0 × 0.1) = 0
and printed it as an instruction.
