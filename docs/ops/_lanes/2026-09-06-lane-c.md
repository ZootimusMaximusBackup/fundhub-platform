Read-only audit. Nothing outside this file was changed.

**Read this first: every hour number on this page is a guess, not a stopwatch.**
Nobody timed this work. I counted commits and lines of changed text, then turned
those counts into hours with a fixed rule. The rule is written below so you can
argue with it. Treat the hours as "this area is big, that area is small", not as

### The formula, in one line

Each commit goes to the one bucket where most of its changed lines landed; ties
go to the biggest bucket by lines.

### What I threw out of the line counts

  cannot count lines in a picture, so it reports nothing and I skipped them.
- **Lockfiles** (`package-lock.json`, `yarn.lock`, `deno.lock`). 11 of them.
  These are auto-written by the computer. Counting them would be counting
  machine typing as human work.

Eight commits changed nothing but pictures or lockfiles. They show as a separate
row so no commit goes missing.

### The hours rule, in one line

20 minutes for every commit, plus 1 minute for every 25 changed lines, and no
single commit may score more than 4 hours.

The widened list is produced by this loop, one line per qualifying day:

```
for d in $(git log --all --since=2026-07-08 --no-merges --format=%ad --date=short | sort -u); do
  n=$(date -j -v+1d -f %Y-%m-%d $d +%Y-%m-%d)
  mk=$(git log --all --since=$d --until=$n --no-merges --name-only --format= \
       | grep -cE 'docs/ads/|clickfunnels-fragments/|homepage-survey')
  code=$(git log --all --since=$d --until=$n --no-merges --name-only --format= \
       | grep -cE '^(src/|api/|db/|netlify/|public/app/)')
  [ "$mk" -gt 0 ] && [ "$code" -gt 0 ] && echo "$d"
done
```
